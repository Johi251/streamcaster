## Receiver auto-generates room code (tag v1.0.3)

Johann meldete: Fire TV Silk-Browser auf `streamcaster.pages.dev/r/`
zeigt keinen Code — nur „No room code in URL. Open this page as /r/<CODE>".

Ursache: apps/receiver/src/main.ts Zeile 51–52 — wenn kein Code in der
URL stand, zeigte die Seite eine tote Fehlermeldung und verband nicht.
Das ist aber der **normale Flow** auf einem TV-Browser: man öffnet /r/,
liest den Code vom Bildschirm und tippt ihn ins Handy ein.

Fix: Receiver generiert per `generateRoomCode()` (crypto.getRandomValues,
6 Zeichen, no-confusable Alphabet) selbst einen Code, zeigt ihn an,
reflektiert ihn via `history.replaceState` in die URL (reload-sicher,
verwaist den Sender nicht bei Reload) und verbindet.

Zwei weitere Fixes im gleichen Commit:
- Stale Fallback-Signaling-URL korrigiert: `johan.workers.dev` →
  `streamcaster.workers.dev` (war im Bundle zwar via VITE_SIGNALING_URL
  überschrieben, aber ein Landmine).
- deploy.mjs-Preflight toleriert abgelaufenen OAuth-Token (Code 9109)
  mit no-op statt hartem Exit — wrangler selbst nutzt intern den
  refresh_token, das Skript liest aber den rohen oauth_token.

Validiert: 12/12 Unit-Tests grün, Typecheck grün, Bundle enthält
getRandomValues + replaceState, alte Fehlermeldung entfernt.
Produktiv redeployed (v1.0.3, Deployment ba634791).
