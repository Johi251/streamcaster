## Root-Cause-Fix (Deploy-Blocker)
`apps/signaling/package.json` hatte **keine** Dependency auf `@streamcaster/shared`. Nach dem Ordner-Move (WorkBuddy AI → 00 PROJEKTE) fehlte der pnpm-Symlink → wrangler/esbuild "Could not resolve @streamcaster/shared". Fix: `"dependencies": { "@streamcaster/shared": "workspace:*" }` + `pnpm install`. Sender/Receiver hatten es korrekt.

## Fire-TV-Installationsfehler: Ursachen + Gegenprobe (29.10., Abend)
- Fehlermeldung „beim parsen des pakets ist ein problem aufgetreten" = `INSTALL_PARSE_FAILED`, also **minSdk**, nicht ABI.
  Gerät: Fire TV Stick 4K 1. Gen, Fire OS 6.7.1.1 = Android 7.1.2 = **API 25**; APK hatte `minSdk 28`.
- Zweiter, unabhängiger Blocker: APK enthielt nur `arm64-v8a`. Fire-TV-Sticks laufen meist mit 32-Bit-Userspace
  (`ro.product.cpu.abi=armeabi-v7a`) auch auf 64-Bit-SoCs.
- **Gegenprobe gebaut** (`.mtest/`): `AndroidManifest.xml` aus dem Release-APK extrahiert, eigener AXML-Parser
  (`axml.py`) lokalisiert `uses-sdk`-Attribute präzise — `minSdkVersion` sitzt bei Offset **6448**, `targetSdkVersion`
  bei 6468 (Byte-Scan vorher war richtig, aber Raten ist unnötig). Wert 0x1c→0x18 gepatcht, per `repack.py`
  (erhält Reihenfolge + compress_type je Entry), `zipalign -f -p 4`, dann `apksigner` **über `java -jar lib/apksigner.jar`** —
  `apksigner.bat` scheitert an Leerzeichen im Pfad (`C:\...\00 PROJEKTE\...`).
  Signatur mit demselben Release-Zertifikat (Cert-SHA-256 unverändert) → als Test-APK `https://streamcaster.pages.dev/t.apk`.
- **ffmpeg-Install-Fehler endgültig erklärt**: nicht Pfad-/Quoting-Problem, sondern **cmd.exe-Limit von 8191 Zeichen**.
  `install-headers` übergibt ~100 absolute Header-Pfade in *einem* `install`-Aufruf; die Zeile wird abgeschnitten,
  das letzte Argument zerfällt → `install: target 'c:/Users/johan/s' is not a directory`.
  Fix: `cmake/InstallFFmpeg.sh` kopiert Libs + Header selbst (identisch auf allen Hosts), kein `make install` mehr.

## Umstieg auf GitHub Actions (Linux) als Referenz-Build
- Grund: Windows-Host bringt gleich drei Probleme mit (8191-Limit, MSYS-Pfadübersetzung, zu abgespecktes Host-Perl
  für OpenSSLs `Configure`). Linux umgeht alle drei.
- `BuildFFmpeg.cmake` portabel gemacht: `--tempprefix=.` und `--host-cc=…` nur noch unter `CMAKE_HOST_WIN32`
  (auf Linux wäre `--host-cc` = Ziel-Compiler für Host-Probes → falsch), `FixFfmpegPaths.cmake` ebenso.
- `.github/workflows/android.yml` neu: checkout mit Submodulen, JDK 21, SDK-Pakete, Gradle-Cache, `assembleRelease`,
  ABI-/SDK-Verifikation via `aapt2 dump badging`, Artifact-Upload. Signierung optional über Repo-Secrets
  (`ANDROID_KEYSTORE_B64` …) — ohne Secrets entsteht ein unsigniertes APK statt eines Fehlers.
- CI-Stolpersteine, die real auftraten und gefixt wurden:
  1. `secrets` ist in `if:` **nicht** verfügbar → Job-`env` und dort prüfen (Workflow wurde sonst schon beim Parsen
     abgelehnt: Run 0 s, keine Jobs, kein Log).
  2. `android-actions/setup-android@v3` ist defekt (will das abgekündigte Paket `tools`) → vorinstalliertes SDK nutzen.
  3. Es gibt **kein** `platforms;android-37`; die API-37-Plattform heißt `platforms;android-37.0`
     (ebenso 37.1/37.2). Ordner im lokalen SDK heißt entsprechend `android-37.0`.
- Version auf **1.0.1 / versionCode 2** angehoben, `minSdk 24`, ABIs `arm64-v8a` + `armeabi-v7a`.
  OpenSSL kann armeabi-v7a bereits out of the box (`OPENSSL_PLATFORM=arm` + `-march=armv7-a`).
