# 2026-10-31

## E2E-Playwright-Suite: von 1/17 auf 17/17 grün (Live)

Erstlauf der zuvor nie ausgeführten Suite ergab 16/17 Fehler. Ursachenanalyse
und Fixes:

### App-Bug (echt, behoben)
- **Receiver ignorierte `?code=` aus der URL.** `parseRoomCode()` existierte in
  `apps/receiver/src/main.ts`, wurde aber **nie aufgerufen** — `ensureRoomCode()`
  überschrieb immer mit einem Zufallscode. Dadurch konnte kein Test einen
  deterministischen Raum öffnen (Sender und Receiver landeten in verschiedenen
  Räumen).
- Fix: `ensureRoomCode()` ruft jetzt `parseRoomCode()` auf und übernimmt einen
  gültigen Code aus `/r/<CODE>` bzw. `/r/?code=<CODE>`; sonst Zufallscode.
  Rückwärtskompatibel (ohne Code unverändert).
- Nebenwirkung: Der Pfad-Form-Deep-Link `/r/<CODE>` funktioniert jetzt ebenfalls.

### Test-Bugs (Suite war nie validiert)
- `pair()` und zwei Pairing-Assertions erwarteten Status-Text `"Sender connected"`,
  die App zeigt aber `"Connected"`. Umgestellt auf robuste CSS-Klassen-Prüfung
  `#status` hat Klasse `connected`.
- QR-Test prüfte `#qr canvas`; der QR wird aber als `<img>` in `#qr-box`
  gerendert → Selektor auf `#qr-box img` korrigiert.

### Build-Fallstrick
- `build:site` ohne `VITE_PROXY_URL` backt einen leeren Proxy ein → In-Page-
  Browser meldet "Proxy not configured" und der iframe bleibt `about:blank`.
  `deploy:all` setzt die Variablen; manueller Build muss sie mitgeben.
- HLS-über-Proxy-Test schlägt lokal fehl, weil der Remote-Proxy `127.0.0.1`
  nicht erreicht — nur gegen die öffentliche URL sinnvoll.

### Deploy
- Site mit `VITE_SIGNALING_URL` + `VITE_PROXY_URL` neu gebaut und auf Cloudflare
  Pages deployt. Live verifiziert: Receiver-Bundle `index-DePN3fCn.js`,
  Sender `index-IfpRZw_F.js`, APK 9.535.890 B / korrekter MIME.
- Ergebnis: **17/17 Playwright-Tests grün gegen `https://streamcaster.pages.dev`**
  (52,6 s, keine Retries).
